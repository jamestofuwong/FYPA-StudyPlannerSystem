# UAT plan: Study Planner System

> Generated by `npm run docs:uat` from `docs/uat/uat-data.js`. Edit that file, not this one.

## 1. Purpose

Academic advisors compare each student with several versions of the study planners by hand. It is slow and often wrong. This session checks that the system does what the client asked for, one test for each requirement. The testers are Heads of Department. The team watches, records and does not help.

## 3. How it runs

- **Who:** at least 2 Heads of Department (testers), one team member who runs the session, one who takes notes.
- **How long:** 31 tests (26 Must, 5 Agreed) in two sessions, on one day with a lunch break or on two days. Session A takes about 1.4 hours (15 tests); Session B takes about 1.5 hours (16 tests).
- **Order:** the sessions follow the order of the tests, from the first start to the Copilot and the web app.
- **Where:** the team's computer, with the installed release build on a new installation. The testers log in to the portal with their own accounts. The team does not see or store a password or a student record. The student website is tested on a staging copy.
- **Method:** the facilitator reads each task. The tester does it and marks Pass, Fail, Blocked or N/A, with a note. The facilitator does not show how. Do not fix anything during the session.
- **Acceptance rule:** the client accepts the system when **all Must tests pass and no Critical or Major defect is open**. An Agreed test that fails is reported and the client decides.
- **Severity:** Critical = student data stored or lost, a crash, or a wrong answer with no warning. Major = a requirement does not work and there is no workaround. Minor = awkward, or there is a workaround. Cosmetic = the look only.
- **Before the session:** `npm run verify:full` passes on the build, the data pack is ready, and the team did one dry run. The dry run confirms the expected results below, which were written from the user guide and the code.

## 4. Data pack

| Item | Use |
|---|---|
| Students A to E | Students whose course and major the Head of Department can state. A is a typical mid-course student who cannot graduate yet. |
| Student F | A first-year student with no major yet. |
| Student H | A student who can graduate. |
| Students I, J, K | I has a failed core unit. J has a unit in progress. K has two Conceded Passes. |
| Student L | A second student for the pathway check. |
| Excel files | A transcript file with its intake, a file with a missing column, and a block of rows to paste with five units. |
| PDF files | An official study planner PDF that is not in the app yet, and a PDF that is not a planner. |
| Class estimation values | The student ID range of one course, and the returning percentage and the number of new students that the Head of Department uses. |
| Staging site and CMS account | The staging student website and a superadmin account for it (never the production site). |
