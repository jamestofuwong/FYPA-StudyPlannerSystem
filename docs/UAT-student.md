# UAT plan: Student Website

> Generated by `npm run docs:uat` from `docs/uat/uat-student-data.js`. Edit that file, not this one.

## 1. Purpose

Students ask advisors the same basic questions again and again: which planner fits them, what a unit is, what is left to study, and who to contact. The student website answers these questions without an advisor. This session checks that it does, one test for each requirement. The testers are students. The team watches, records and does not help. Not part of this session: the CMS for staff, and the use of the website on a phone and with a keyboard only.

**Must** = a job that the website must do, or a rule that keeps data safe. Every test here is a Must test, and all must pass.

## 3. How it runs

- **Who:** at least 3 students from different years, one team member who runs the session, one who takes notes.
- **How long:** 12 tests (all Must) in one session of about 1.2 hours.
- **Where:** the staging copy of the website, never the production site. A student uses their own phone or computer.
- **Method:** the facilitator reads each task. The tester does it and marks Pass, Fail, Blocked or N/A, with a note. The facilitator does not show how. Do not fix anything during the session.
- **Acceptance rule:** the client accepts the website when **all tests pass and no Critical or Major defect is open**.
- **Severity:** Critical = student data stored or shown to the wrong person, or a page that stops. Major = a requirement does not work and there is no workaround. Minor = awkward, or there is a workaround. Cosmetic = the look only.
- **Before the session:** `npm run verify:full` passes on the build, the staging site has the seed data (`npm run db:seed`), the data pack is ready, and the team did one dry run. The dry run confirms the expected results below, which were written from the code and the pages.

## 5. Tests

### SC-01: Find a planner

**Requirement:** S1 | **Priority:** Must

1. Open the home page (Study Planners). Read the number of planners.
2. Type the name of a major in the search box, then clear it with the X button. Type some letters that no planner has.
3. Select one course, one major and one intake year, one group at a time. In each group, select All.

**Expected:** The page lists the planners as cards with the course code, the major, the intake, the length and the number of units. The number above the cards says how many are shown. The search and the three filters narrow the list and work together, and All removes only its own filter. Letters with no match show "No planners found" and no error.

### SC-02: Read a planner, semester by semester

**Requirement:** S1 | **Priority:** Must

1. Open the planner of the data pack (the card links to it).
2. Read the top of the page and the first two tables.
3. Select a unit code in a table.

**Expected:** The top shows the course, the major and the intake. Each table has one heading with the year and the semester and its month, such as "Year 1 Semester 1 - Mar 2026". The units have colours by type, and a legend with the totals is on the right. The prerequisites show beside each unit. The unit code opens the page of that unit.

**Result (Pass / Fail / Blocked / N/A):** &nbsp;&nbsp; **Notes:**

### SC-03: Search and filter the units

**Requirement:** S2 | **Priority:** Must

1. Open Units. Search by a unit code. Then by a word of a unit name.
2. Choose a year level. Then clear the search.
3. Go to the next page of the list and back.

**Expected:** The search finds the units by code and by name. The year level narrows the list. The pages of the list work. A search with no match shows "No units found".

**Result (Pass / Fail / Blocked / N/A):** &nbsp;&nbsp; **Notes:**

### SC-04: Read the details of a unit

**Requirement:** S2 | **Priority:** Must

1. Open the unit with full details of the data pack.
2. Read the sidebar and every section of the page.

**Expected:** The page shows the name, the code, the credit points, the year level and when the unit runs. The sidebar lists the prerequisite, the co-requisite and the anti-requisite. The page shows the overview, the learning outcomes, the content and the assessment table with the weights.

**Expected:** The official page of that unit opens in a new tab on the university website, and the student website stays open in its own tab. The MPU unit has no such button, because the university site has no page of its own for it.

**Expected:** The unit page says that details are not available, and still shows the code, the credit points and the requisites. It does not crash. The wrong address shows "Page not found" with links back to the main pages.

### SC-07: Build a plan from the start

**Requirement:** S3 | **Priority:** Must

1. Open Plan Builder. Read the hint beside the Generate button.
2. Choose the course, the major and the intake of Student X (data pack), and select Generate Study Plan.
3. Write down the number beside Remaining in the summary.

**Expected:** Before a major is chosen, the page says to select a course and a major. After Generate, a plan shows for every semester of the course, with the units and their prerequisites. The summary shows the intake, the course, the major, Completed 0 and the number Remaining. A note tells the student to check with an advisor.

**Result (Pass / Fail / Blocked / N/A):** &nbsp;&nbsp; **Notes:**

### SC-08: Add the completed units

**Requirement:** S3 | **Priority:** Must

1. Under Units Completed, select "+ Add unit" in Semester 1 and add the five completed units of Student X, one at a time. After each one, open the search list again.
2. Select Generate Study Plan.
3. Change the intake year.

**Expected:** A unit that was added is not offered in the search list again, so it cannot be added twice. The page says "5 units marked as completed". The summary shows Completed 5 units, and Remaining is lower than the number from SC-07 (for the planner of the data pack, 25 instead of 29, because the elective unit fills an elective slot). The five units show as completed in the plan. The change of the intake year removes the old plan, so the screen never shows a plan that does not match the choices.

**Result (Pass / Fail / Blocked / N/A):** &nbsp;&nbsp; **Notes:**

### SC-09: Import the completed units from an Excel file

**Requirement:** S3 | **Priority:** Must

1. In the Plan Builder, choose the course, the major and the intake of Student X. Select Import from Excel and choose the results file of the data pack.
2. Read the message, and the three semester tables under Units Completed.
3. Select Generate Study Plan. Then choose a file that is not an Excel file (for example a PDF).

**Expected:** The page says "Imported 15 units in 3 semesters", and that the file starts in 2026_MAR_S1. Semester 1, 2 and 3 hold five units each, the ones of the file in the order of its terms. The summary then shows Completed 15 units, and Remaining is 19 for the planner of the data pack (29 with no units). The file is read on the device: the page does not upload it. The PDF is refused with a message that the file must be an Excel .xlsx file, and the units already on the page stay.

**Result (Pass / Fail / Blocked / N/A):** &nbsp;&nbsp; **Notes:**

### SC-10: The plan follows the rules

**Requirement:** S3 | **Priority:** Must

1. Generate the plan of SC-08 again. Check that each unit comes after its prerequisites.
2. Check that no semester has more units than the planner has for a normal semester.
3. Read the notices above the plan.

**Expected:** No unit comes before its prerequisite and no semester is over the normal load. A unit that runs only in summer or winter is not put in a normal semester, and a notice names it (for the planner of the data pack, MPU3212 and ICT20016).

**Result (Pass / Fail / Blocked / N/A):** &nbsp;&nbsp; **Notes:**

### SC-11: What the student enters is not stored

**Requirement:** S5 | **Priority:** Must

1. Add completed units, or import the results file, and generate a plan. Refresh the page.
2. Open the website in a private window, or another browser.
3. Close the tab and open the website again.
4. (Facilitator) After the session, list the tables of the staging database.

**Expected:** After a refresh in the same tab the entries are still there, because the tab keeps them. In the other window and after the tab is closed, the builder is empty. The database has no table for students, transcripts or plans of students. It holds only planners, units, help content and CMS accounts.
