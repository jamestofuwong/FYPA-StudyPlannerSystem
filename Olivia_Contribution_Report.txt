1. SUMMARY
------------------------------------------------------------------------

This report records work on the advisor Major Detection dashboard and the
student-facing Plan Builder. The work focused on making graduation
eligibility trustworthy, keeping database code off the student browser,
and making the plan builder usable with live course data.

Four commits on branch Olivia are described below, plus uncommitted
Major Detection UI work completed after 18 September 2026.

------------------------------------------------------------------------
2. COMMIT: Fix Graduation Check  (c43ce8e, 13 September 2026)
------------------------------------------------------------------------

Area: Advisor dashboard — Graduation Check

Problem
  Eligibility used a local estimate (matched planner units × 12.5 CP,
  with a special MPU cap). That figure did not match the credit totals
  shown on the student identity card, so a student could look eligible
  in one place and ineligible in another.

What was done
  - Credit totals now come from the portal (or import): creditsCompleted
    and creditsRequired (required defaults to 300 if missing).
  - Eligibility requires: no missing core/major units, no missing
    prescribed electives, and completed CP ≥ required CP.
  - The credit line and progress bar use the same numbers.
  - Dashboard tests were updated so eligible and ineligible cases supply
    creditsCompleted / creditsRequired on the mock scrape result.

------------------------------------------------------------------------
3. COMMIT: fix bug  (8e154c0, 16 September 2026)
------------------------------------------------------------------------

Area: Student Plan Builder — server-side plan generation

Problem
  generatePlan ran Prisma / PostgreSQL code in the browser bundle.
  Those packages need Node networking APIs, which broke client builds.

What was done
  - Added POST /api/generate-plan.
  - Added a server-only helper (generatePlanOnServer) that loads the
    planner from the database and marks completed units.
  - Client generatePlan() now calls that API instead of Prisma.
  - Marked planners.ts and prisma.ts as server-only.
  - Configured Next.js to treat pg and @prisma/adapter-pg as server
    packages, and generate the Prisma client on install.

------------------------------------------------------------------------
4. COMMIT: Improve plan builder UX and nav loading
           (af27cf5, 16 September 2026)
------------------------------------------------------------------------

Area: Student Plan Builder and site navigation

Plan Builder
  - Drafts are saved in sessionStorage (intake, course, majors,
    completed units) and restored when the student returns.
  - “Add unit” opens a full list immediately. Units for the selected
    course appear first; other units are grouped separately.
  - Students can filter by code or name without typing first.
  - Major / second-major fields stay hidden until a course is chosen.

Navigation
  - Clicking a tab shows a loading overlay until the next page is ready.
  - The active tab updates as soon as the click happens, so the bar
    does not lag behind the route change.

------------------------------------------------------------------------
5. COMMIT: Update PlanBuilderClient.tsx  (f23aa43, 18 September 2026)
------------------------------------------------------------------------

Area: Student Plan Builder — live database planners

What was done
  - Removed mock course IDs (bcs, bbus, beng).
  - Course and major lists come from database planner options
    (courseId and plannerId).
  - Intake is separate month and year fields, not one combined string.
  - Second-major dropdown was removed from this screen.
  - Suggested units are chosen from the course name (computing,
    business, engineering) instead of mock IDs.
  - Saved drafts use the new fields. Older drafts still keep completed
    units so students do not lose that list.

6. FOLLOW-ON WORK (uncommitted at time of writing)
------------------------------------------------------------------------

Area: Advisor Major Detection — match results and Graduation Check UI

After matching a student to planners, results were a single long page.
They were split so ranked majors and result sections can be opened as
tabs (Analytics, Graduation, Unit Plan, Minors, Extended Plan).

Graduation Check was redesigned as:
  - a status card (Eligible / Ineligible and credit progress);
  - Core & Major and Prescribed Electives as two separate cards beside
    each other, listing remaining units with code, full name, and
    semester in the same row style as Analytics.

Dashboard tests were updated to open the Graduation / Unit Plan /
Extended Plan tabs where those sections now live.
